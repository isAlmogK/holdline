# Holdline Phase 1 Step 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the shared contract changes Phase 1's three parallel tracks build on: the lookup operand `doc(P).f`, the optional project config, and the file-patch golden harness with skeletons of the two new golden apps.

**Architecture:** All changes are additive to `@holdline/core` and `holdline` (CLI). The lookup operand is a new string form of `Operand`; implication treats it like any other string operand, and the test generator learns to seed looked-up documents. The config is a zod-validated `.holdline/config.yaml` passed to analyzers through `AnalyzerContext`. The golden harness copies an example app to a temp folder, applies a unified-diff breakage with `git apply`, and runs `scan` + `check` in process.

**Tech Stack:** TypeScript 5.9, Node 20+, pnpm workspaces, Vitest 5, zod 4, yaml 2.

**Spec:** [`docs/superpowers/specs/2026-10-21-data-layers-design.md`](../specs/2026-10-21-data-layers-design.md), section 2. Reference docs to keep true: [`docs/reference/facts.md`](../../reference/facts.md), [`docs/reference/rules-file.md`](../../reference/rules-file.md).

## Global Constraints

- Node 20 or newer; ESM only; relative imports end in `.js`.
- TypeScript `strict: true`; no `any` in exported signatures; validate every boundary input with zod.
- Holdline makes no network calls. No model decides whether a check passes.
- Never pass silently: when Holdline can't prove something it reports `violation`, `stale` or `unknown`; `opaque` never satisfies a requirement; the test generator skips (with a reason) anything it can't build exact worlds for.
- Exit codes: 0 clean, 1 violation or unapproved edit (with `--strict` also stale or unknown), 2 usage or config error, 3 analyzer or internal error.
- One responsibility per file; prefer files under 200 lines.
- Never commit DogBase code, rules or facts.
- Every behavior change updates `docs/reference/facts.md` or `docs/reference/rules-file.md` in the same commit.
- Conventional commit messages ending with the `Co-Authored-By:` trailer naming the model that wrote the commit. Work on branch `feat/phase-1-step-0`, never on `main`.

```ts
const LOOKUP = String.raw`doc\(/[^()]*\)\.[A-Za-z0-9_]+(?:\.[A-Za-z0-9_]+)*`
export const OPERAND_PATTERN = new RegExp(
  String.raw`^(actor\.uid|actor\.role|actor\.claim\.[A-Za-z0-9_.]+|resource\.[A-Za-z0-9_.]+|incoming\.[A-Za-z0-9_.]+|param\.[A-Za-z0-9_]+|${LOOKUP})$`,
)

const LOOKUP_PARTS = /^doc\((\/[^()]*)\)\.([A-Za-z0-9_]+(?:\.[A-Za-z0-9_]+)*)$/

export function parseLookup(o: string): { path: string; field: string } | undefined {
  const m = LOOKUP_PARTS.exec(o)
  return m ? { path: m[1]!, field: m[2]! } : undefined
}

export function isLookupOperand(o: Operand): o is string {
  return typeof o === 'string' && LOOKUP_PARTS.test(o)
}
```
Update the `OperandSchema` error message to list `doc(<path>).<field>`.

- [ ] **Step 5: Implement test generation in `testgen.ts`**

- Process atoms that use a lookup operand after plain atoms and together with `exists` atoms (lookup paths may need resource values).
- Satisfy:
  - `eq(doc(P).f, v)` (either side): resolve `P` with `resolveDoc`; set field `f` of the seed doc at that path to `v` (literal) or to the other side's value (fixed or newly created `value-N`).
  - `in(x, doc(P).f)`: get or create the value of `x` (fixed, or `value-N` assigned to `x`), then set field `f` of the doc at `P` to `[value]`.
  - Lookup operands with dotted fields, or used with `ne`/`lt`/`gt`, throw `Unsupported`.
- Seed docs from `exists` atoms and lookups on the same resolved path merge into one seed entry (fields combined).
- Break:
  - For an atom whose other side is a `resource.`/`incoming.` operand, break that side (existing rule).
  - Otherwise set the lookup field to `'other-value'` (for `eq`), or to `['other-value']` (for `in` with the lookup on the right).
- `readsStoredRecord` treats `{resource.` inside a lookup path as reading the record.

- [ ] **Step 3: Implement `config.ts`**

```ts
import { readFile } from 'node:fs/promises'
import { join } from 'node:path'
import YAML from 'yaml'
import { z } from 'zod'

const Globs = z.array(z.string().min(1)).min(1)

export const HoldlineConfigSchema = z.looseObject({
  postgres: z.strictObject({ migrations: Globs.optional(), dialect: z.enum(['supabase', 'plain']).optional() }).optional(),
  firestore: z.strictObject({ rules: Globs.optional() }).optional(),
  storage: z.strictObject({ rules: Globs.optional() }).optional(),
})
export type HoldlineConfig = z.output<typeof HoldlineConfigSchema>

export class ConfigError extends Error {
  constructor(message: string) { super(message); this.name = 'ConfigError' }
}

export const configPath = (root: string) => join(root, '.holdline/config.yaml')

export async function loadConfig(root: string): Promise<HoldlineConfig> {
  let text: string
  try {
    text = await readFile(configPath(root), 'utf8')
  } catch (e) {
    if ((e as NodeJS.ErrnoException).code === 'ENOENT') return {}
    throw e
  }
  let raw: unknown
  try {
    raw = YAML.parse(text)
  } catch (e) {
    throw new ConfigError(`.holdline/config.yaml: invalid YAML: ${e instanceof Error ? e.message : String(e)}`)
  }
  const parsed = HoldlineConfigSchema.safeParse(raw ?? {})
  if (!parsed.success) throw new ConfigError(`.holdline/config.yaml: ${z.prettifyError(parsed.error)}`)
  return parsed.data
}
```
If `z.looseObject` is not available in the installed zod 4 version, use `z.object({...}).passthrough()` / `.loose()`; the test for unknown sections decides.

```ts
import { execFile } from 'node:child_process'
import { cp, mkdtemp, readdir } from 'node:fs/promises'
import { existsSync, readdirSync } from 'node:fs'
import { tmpdir } from 'node:os'
import { join } from 'node:path'
import { fileURLToPath } from 'node:url'
import { promisify } from 'node:util'
import { runCli } from './project.js'

const examples = fileURLToPath(new URL('../../../../examples/', import.meta.url))

export async function runPatchedApp(appDir: string, patchFile?: string) {
  const root = await mkdtemp(join(tmpdir(), 'holdline-golden-'))
  await cp(appDir, root, {
    recursive: true,
    filter: src => !/[/\\](breakages|node_modules)([/\\]|$)/.test(src.slice(appDir.length)),
  })
  await cp(join(appDir, 'expected-rules.yaml'), join(root, 'holdline.rules'))
  if (patchFile) {
    try {
      await promisify(execFile)('git', ['apply', '--whitespace=nowarn', patchFile], { cwd: root })
    } catch (e) {
      throw new Error(`git apply ${patchFile} failed: ${e instanceof Error ? e.message : String(e)}`)
    }
  }
  const scan = await runCli(['scan'], { cwd: root })
  const checkOut = await runCli(['check', '--format', 'json', '--strict'], { cwd: root })
  return { root, scan, check: { code: checkOut.code, json: JSON.parse(checkOut.stdout) } }
}

export function goldenApps(): { name: string; dir: string; breakages: string[] }[] {
  return readdirSync(examples)
    .filter(name => name.startsWith('golden-'))
    .map(name => ({ name, dir: join(examples, name) }))
    .filter(app => existsSync(join(app.dir, 'breakages')))
    .map(app => ({
      ...app,
      breakages: readdirSync(join(app.dir, 'breakages')).filter(f => f.endsWith('.patch')).sort().map(f => join(app.dir, 'breakages', f)),
    }))
    .filter(app => app.breakages.length > 0)
}
```
Remove the unused `readdir` import if typecheck flags it. `git apply` inside a folder that is not a git repository applies the diff to the working files, which is what we want.
