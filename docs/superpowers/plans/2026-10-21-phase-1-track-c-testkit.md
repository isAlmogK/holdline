# Phase 1 Track C: `holdline test` and the database test runner. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the generated `.holdline/tests/*.yaml` cases against a real Postgres (PGlite, in process) and the Firebase emulator, add invariant test generation, and ship it as `holdline test`.

**Architecture:** Core keeps test generation (pure, deterministic): a gap fix for Storage seeds, a shared filler module, and invariant generation behind an optional `facts` argument to `generateTests`. A new package `packages/testkit` runs cases: a Postgres runner (fresh PGlite per test file, one rolled-back transaction per case) and a Firestore/Storage runner (`@firebase/rules-unit-testing` v6, inside `firebase emulators:exec` unless an emulator is already running). `packages/cli` adds a thin `test` command that regenerates stale files, calls the testkit and prints the report.

**Tech Stack:** TypeScript (ESM, strict), pnpm workspace, vitest, zod, `@electric-sql/pglite` 0.5, `@firebase/rules-unit-testing` 6 with `firebase` 13, `tsx` (to run the emulator worker), commander.

**Spec:** [docs/superpowers/specs/2026-10-21-data-layers-design.md](../specs/2026-10-21-data-layers-design.md) sections 5 and 8, plus "As built (step 0)" (the Storage seed gap).

## Global Constraints

- ESM, strict TypeScript, relative imports end in `.js`. Validate boundaries with zod. One responsibility per file; split files that pass about 200 lines.
- No model decides pass/fail. Holdline makes no network calls (the emulator is local) and ships no model client.
- Never a silent pass: a case that cannot run is a failure (`actual: 'error'`), a runner that cannot start is an infrastructure failure (exit 3).
- Exit codes: 0 every case passes, 1 any case fails, 2 usage or config errors, 3 a runner cannot start (no Java, no `firebase-tools`, PGlite or migration failure). 3 wins over 1.
- Test values: generated strings (`user-1`, `value-1`) map to column types deterministically: `uuid` → UUID v5 of the string (fixed namespace), numbers → a stable small integer, otherwise the string. Same mapping for `as.uid` → `sub`.
- Postgres: superuser seeds with `SET LOCAL session_replication_role = replica`; actor runs as `authenticated` (supabase) / `anon` for `as: null`, or `holdline_actor` (plain); claims via `set_config('request.jwt.claims', json, true)`. Reject codes: `23502`, `23503`, `23505`, `23514`, `22P02`. Reject cases run as superuser with foreign keys on.
- Firebase: `initializeTestEnvironment({ projectId: 'holdline-test', firestore: { rules }, storage: { rules } })`; reuse `FIRESTORE_EMULATOR_HOST` / `FIREBASE_STORAGE_EMULATOR_HOST` when set, else wrap in `firebase emulators:exec --only firestore,storage --project holdline-test`. Missing `firebase` or Java → exit 3 with an install hint.
- Emulator tests are tagged `@emulator` in their `describe` name and skipped with a printed message when the emulator cannot start.
- Contracts are frozen: `TestFileSchema` / `TestCaseSchema` in `packages/core/src/testcase.ts` do not change shape. `generateTests` gains only an optional third parameter.
- Files owned by this track: `packages/testkit/**`, `packages/cli/src/commands/test.ts`, the `test` registration in `packages/cli/src/main.ts`, `packages/core/src/testgen*.ts`, `testcase.ts`, test-runner rows of the reference docs. `packages/cli/src/commands/approve.ts` changes by one call (pass cached facts).
- Never commit DogBase code, rules or facts. Conventional commits on branch `claude/phase-1-testkit-6cb172`, never `main`. Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Commands: `pnpm test` (all tests), `pnpm typecheck`, `pnpm holdline <command>`. Run one file with `pnpm vitest run <path>`.

## Decisions made in this plan (record them in the spec's As built)

| Decision | Why |
|---|---|
| `holdline test` also takes `--facts <file>` (like `check`), used only when invariant files must be (re)generated | Invariant generation needs table facts; tests and fixtures pass a facts file before Track A's analyzer exists |
| An approved rule with `test` enforcement and no test file gets its file generated by `holdline test` (reported as "generated") | Deterministic, and invariant files cannot be written by `approve` without facts |
| `approve` passes the cached facts (`.holdline/cache/facts.json`, if present) to `generateTests` | Writes invariant files at approval when a scan has run; never scans by itself |
| `reject` passes on any of the five constraint SQLSTATEs (the case format has no code field) | The allow case proves the complete row is valid, so the only change in a reject case is the broken column |
| Filler: numbers are `1` (not `0`), and a column whose CHECK is `col = ANY (ARRAY['a', ...])` or `col IN ('a', ...)` gets its first literal | `amount > 0` and `status IN (...)` are common and would make every seed fail (CHECKs stay on in replica mode) |
| Generated rows leave primary-key columns out unless the rule names them or they are foreign keys; the runner assigns keys | Two rows of a `unique` case must differ in their key so only the unique constraint can reject |
| Claims whose string value was mapped to a UUID elsewhere in the case get the same UUID | `auth.jwt() ->> 'org_id' = org_id::text` must agree with the seeded uuid column |
| Storage seed `data` becomes custom metadata: strings as is, numbers and booleans as strings, `null` dropped, other values JSON | Custom metadata values are strings |
| Firebase cases run in a worker process started by `firebase emulators:exec` (`node --import tsx worker.ts in.json out.json`) rather than re-running the whole `holdline test` command | The CLI is also called in-process (tests); the worker gets exactly the Firebase files and writes results to a file |
| Storage invariants are skipped ("storage invariants are not generated; check them statically") | The spec lists Firestore invariants only |

- [ ] **Step 3: Implement `testgen-filler.ts`**

```ts
// Filler for a column a test row must set but the case does not care about ("complete row", spec 5.2).
// The generator and the Postgres runner share it, so a generated row and a runtime-completed row agree.
// `uuid` filler is a test value string: the runner maps every string in a uuid column to a UUID v5.

export type FillerContext = { enumLabels?: readonly string[]; checks?: readonly string[] }

const NUMERIC = /^(smallint|integer|bigint|int[248]?|numeric|decimal|real|double precision|float[48]?|serial|bigserial|smallserial)\b/

export function fillerValue(column: { name: string; type: string }, ctx: FillerContext = {}): unknown {
  const type = column.type.toLowerCase()
  if (type.endsWith('[]')) return []
  if (ctx.enumLabels && ctx.enumLabels.length > 0) return ctx.enumLabels[0]
  const literal = checkLiteral(column.name, ctx.checks ?? [])
  if (literal !== undefined) return literal
  if (type === 'uuid') return 'filler'
  if (NUMERIC.test(type)) return 1
  if (type === 'boolean' || type === 'bool') return false
  if (type.startsWith('timestamp')) return '1970-01-01T00:00:00Z'
  if (type === 'date') return '1970-01-01'
  if (type === 'json' || type === 'jsonb') return {}
  return 'x'
}

// The first string literal of a CHECK that limits `column` to a list: `col = ANY (ARRAY['a'::text, ...])`
// (how Postgres prints `col IN ('a', ...)`) or `col IN ('a', ...)`.
export function checkLiteral(column: string, checks: readonly string[]): string | undefined {
  const col = column.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
  const forms = [
    new RegExp(String.raw`\(?"?${col}"?\)?(?:::\w+)?\s*=\s*ANY\s*\(\s*\(?ARRAY\s*\[\s*'((?:[^']|'')*)'`, 'i'),
    new RegExp(String.raw`\(?"?${col}"?\)?\s+IN\s*\(\s*'((?:[^']|'')*)'`, 'i'),
  ]
  for (const check of checks) {
    for (const form of forms) {
      const m = form.exec(check)
      if (m) return m[1]!.replace(/''/g, "'")
    }
  }
  return undefined
}
```

- [ ] **Step 5: Implement `testgen-invariant.ts` and wire it in `testgen.ts`**

```ts
import { FactIndex } from './fact-index.js'
import type { Facts, Table } from './facts.js'
import { normalizeTable } from './paths.js'
import type { InvariantRule } from './rules.js'
import type { TestCase, TestFile } from './testcase.js'
import { fillerValue } from './testgen-filler.js'

type Row = Record<string, unknown>
type Seed = { path: string; data: Row }
export const INVALID_ENUM = '__holdline_invalid__'

// Postgres invariant cases (spec 5.4): one complete valid row that must insert, then rows that break the
// invariant and must be rejected. They run as superuser with foreign keys on, so every foreign key the row
// sets gets a seeded parent row. Primary-key columns are left to the runner unless the rule names them or
// they are foreign keys, so two rows of a `unique` case differ in their key.
export function postgresInvariantCases(rule: InvariantRule & { target: { store: 'postgres' } }, facts: Facts | undefined): Pick<TestFile, 'cases' | 'skipped'> {
  const path = normalizeTable(rule.target.table)
  if (rule.kind === 'check') return { cases: [], skipped: ['check expressions are tested statically only'] }
  const table = facts ? new FactIndex(facts).table(path) : undefined
  if (!table) return { cases: [], skipped: [`table ${path} is not in the facts; run holdline scan, then holdline test`] }
  const { row, parents } = validRow(rule, table)
  const create = (name: string, data: Row, expect: 'allow' | 'reject', seed: Seed[] = parents): TestCase =>
    ({ name, as: null, seed: structuredClone(seed), do: { op: 'create', path, data: structuredClone(data) }, expect })
  const cases = [create('create: a complete valid row inserts', row, 'allow')]
  const cols = rule.columns.join(', ')
  switch (rule.kind) {
    case 'not-null':
      for (const c of rule.columns) cases.push(create(`create: rejects ${c} null`, { ...row, [c]: null }, 'reject'))
      break
    case 'fk': {
      const missing = Object.fromEntries(rule.columns.map((c, i) => [c, `missing-${i + 1}`]))
      cases.push(create(`create: rejects ${cols} with no matching ${normalizeTable(rule.references!.table)} row`, { ...row, ...missing }, 'reject'))
      break
    }
    case 'unique':
      cases.push(create(`create: rejects a second row with the same ${cols}`, row, 'reject', [...parents, { path, data: row }]))
      break
    case 'enum':
      for (const c of rule.columns) cases.push(create(`create: rejects ${c} '${INVALID_ENUM}'`, { ...row, [c]: INVALID_ENUM }, 'reject'))
      break
  }
  return { cases, skipped: [] }
}

function validRow(rule: InvariantRule, table: Table): { row: Row; parents: Seed[] } {
  const fkCols = new Set(table.foreignKeys.flatMap(fk => fk.columns))
  const pk = new Set(table.primaryKey)
  const row: Row = {}
  for (const col of table.columns) {
    const named = rule.columns.includes(col.name)
    const required = !col.nullable && col.default === undefined
    if (!named && !required) continue
    if (pk.has(col.name) && !named && !fkCols.has(col.name)) continue
    if (fkCols.has(col.name)) row[col.name] = `${col.name}-1`
    else if (rule.kind === 'enum' && named) row[col.name] = rule.values![0]
    else row[col.name] = fillerValue(col, {
      enumLabels: table.enums.find(e => e.column === col.name)?.values,
      checks: table.checks.map(c => c.expr),
    })
  }
  const parents: Seed[] = []
  for (const fk of table.foreignKeys) {
    if (!fk.columns.every(c => c in row)) continue
    const data = Object.fromEntries(fk.references.columns.map((rc, i) => [rc, row[fk.columns[i]!]]))
    parents.push({ path: normalizeTable(fk.references.table), data })
  }
  return { row, parents }
}
```

```ts
import { FactIndex } from './fact-index.js'
import type { Atom } from './expr.js'
import type { Facts } from './facts.js'
import { expand, flattenAnd } from './logic.js'
import type { DataAccessRule, InvariantRule } from './rules.js'
import type { TestCase, TestFile } from './testcase.js'
import { toCase } from './testgen-case.js'
import { holds } from './testgen-eval.js'
import { INVALID_ENUM } from './testgen-invariant.js'
import { satisfy } from './testgen-satisfy.js'
import { set, Unsupported, type World } from './testgen-world.js'

// Firestore invariant cases (spec 5.4): `create` against the write rules, allowed with the field valid and
// denied with it missing (`not-null`) or not in the list (`enum`). The allowed world satisfies one of the
// target's create policies from the facts, so the case tests the field and not the rest of the condition.
export function firestoreInvariantCases(rule: InvariantRule, facts: Facts | undefined): Pick<TestFile, 'cases' | 'skipped'> {
  if (rule.target.store !== 'firestore') throw new Error('firestore invariants only')
  const target = rule.target
  const none = { cases: [], skipped: [`create: no create policy for ${target.path} in the facts that cases can be generated for`] }
  if (!facts || (rule.kind !== 'not-null' && rule.kind !== 'enum')) return none
  for (const policy of new FactIndex(facts).policies(target, 'create')) {
    const access: DataAccessRule = { id: rule.id, text: rule.text, type: 'data-access', target, ops: ['create'], requires: policy.condition, evidence: [], status: 'approved' }
    const world = allowWorld(access, rule)
    if (!world) continue
    const cases: TestCase[] = []
    const allowName = rule.kind === 'enum' ? `create: allowed with a valid ${rule.columns.join(', ')}` : `create: allowed with ${rule.columns.join(', ')} set`
    cases.push(toCase(allowName, world, world, access, 'create', 'allow'))
    for (const c of rule.columns) {
      const denied = structuredClone(world)
      if (rule.kind === 'enum') denied.incoming[c] = INVALID_ENUM
      else delete denied.incoming[c]
      const name = rule.kind === 'enum' ? `create: denied with ${c} '${INVALID_ENUM}'` : `create: denied without ${c}`
      cases.push(toCase(name, denied, denied, access, 'create', 'deny'))
    }
    return { cases, skipped: [] }
  }
  return none
}

function allowWorld(access: DataAccessRule, rule: InvariantRule): World | undefined {
  const parts = flattenAnd(expand(access.requires, new Map()))
  if (!parts.every((p): p is { atom: Atom } => 'atom' in p)) return undefined
  const atoms = parts.map(p => p.atom)
  const pins = rule.kind === 'enum' ? rule.columns.map(c => ({ operand: `incoming.${c}`, value: rule.values![0] })) : []
  try {
    const w = satisfy(atoms, access, { pins })
    if (rule.kind === 'not-null') for (const c of rule.columns) if (w.incoming[c] === undefined) set(w, `incoming.${c}`, `present-1`)
    return atoms.every(a => holds(w, a, 'create')) ? w : undefined
  } catch (e) {
    if (e instanceof Unsupported) return undefined
    throw e
  }
}
```

Runner behavior (`firebase-runner.ts`, `firebase-ops.ts`):
- `initializeTestEnvironment({ projectId: 'holdline-test', firestore: { rules }, storage: { rules } })` (omit a section without rules; for a Storage file, Firestore rules are needed only when present). One environment per run; `cleanup()` at the end.
- Per case: `clearFirestore()` (and `clearStorage()` when storage is configured); seed inside `withSecurityRulesDisabled`: Firestore seeds → `setDoc(doc(ctx.firestore(), path), data)`; in storage files, `store: 'storage'` seeds → `uploadString(ref(ctx.storage(), path), '', 'raw', { customMetadata: toMetadata(data) })`, `store: 'firestore'` → `setDoc`.
- Context: `as` → `authenticatedContext(as.uid, as.claims)`; `null` → `unauthenticatedContext()`. (`as.role` has no Firestore meaning and is ignored.)
- Ops: table in spec 5.3 for Firestore (`getDoc`, `getDocs(collection)`, `setDoc`, `updateDoc`, `deleteDoc`); Storage: `getMetadata` (read), `listAll` (list), `uploadString(ref, '', 'raw', { customMetadata })` (create, update), `deleteObject` (delete).
- Outcome: op resolves → `allow`; rejects with code `permission-denied` (Firestore) or `storage/unauthorized` (Storage) → `deny`; anything else → `error` with the message. `passed`: `expect === 'allow'` needs `allow`; `deny` and `reject` need `deny` (spec: `assertFails` for both).
- `toMetadata(data)`: strings as is, numbers and booleans `String(v)`, `null`/`undefined` dropped, other values `JSON.stringify`.

Emulator orchestration (`emulator.ts`):
1. Needs Storage = any file with `store: 'storage'`. When `FIRESTORE_EMULATOR_HOST` is set (and `FIREBASE_STORAGE_EMULATOR_HOST` when Storage is needed): run `runFirebaseFiles` in-process.
2. Else probe `firebase --version` (spawn; `ENOENT` → `{ infra: 'firebase-tools is not installed: ' + HINT }`) and `java -version` (`ENOENT` → `{ infra: 'Java is not installed: ' + HINT }`).
3. Temp dir with `firebase.json`: `{ emulators: { firestore: { host: '127.0.0.1', port }, storage: { host: '127.0.0.1', port }, hub: { port }, logging: { port }, ui: { enabled: false } }, firestore: { rules: 'firestore.rules' }, storage: { rules: 'storage.rules' } }`, free ports from `net.createServer().listen(0)`, the two rules files (a deny-all file when one is missing), `input.json`.
4. Worker command: `"<process.execPath>" --import "<tsx loader file URL>" "<firebase-worker.ts path>" "<in.json>" "<out.json>"`. The tsx loader URL: `pathToFileURL(join(dirname(createRequire(import.meta.url).resolve('tsx/package.json')), 'dist/loader.mjs')).href`. The worker path: `fileURLToPath(new URL('./firebase-worker.ts', import.meta.url))`.
5. Spawn `firebase emulators:exec --only firestore,storage --project holdline-test --config <tmp>/firebase.json <command>` with `cwd` = temp dir, collecting stdout+stderr, timeout 180 s.
6. `out.json` exists → parse with zod (`z.record(z.string(), z.array(CaseResultSchema))`) → `{ results }`. Otherwise `{ infra: 'the Firebase emulator did not start: <last 15 output lines>' }`, plus `HINT` when the output mentions Java.
7. Remove the temp dir.

`firebase-worker.ts`: reads `argv[2]`, validates `{ firestoreRules?, storageRules?, files }` with zod (`TestFileSchema` from core for files), calls `runFirebaseFiles`, writes `argv[3]`, exits 0; on error prints the stack and exits 1.
